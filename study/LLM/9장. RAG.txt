1. 임베딩과 유사도 계산

- 문장을 1차원 숫자 배열인 임베딩 벡터로 변환하는 작업 처리

- 사용 모델
	- OpenAI text-embedding-3-small : 1536차원
	- OpenAI text-embedding-3-large : 3072차원
	- Upstage embedding-query : 4096차원, 한국어 환경에서 성능 우수
	- Upstage solar-embedding-1-large-query, solar-embedding-2-query

- 유사도 계산 방식
	- 유클리드 : 두 벡터 사이의 최단 직선 거리 계산
	- 코사인 유사도 : 두 벡터가 이루는 각도(방향) 기준 계산
	- dot product : 성분별 곱의 합으로 크기와 방향을 함께 고려한 계산

- 의미가 가까운 문장일수록 코사인 유사도가 높게 출력되며 한국어 문장은 Upstage 모델이 더 적합

	ex)
	import numpy as np
	from openai import OpenAI

	def cosine_similarity(v1, v2):
		'두 벡터의 코사인 유사도를 반환'
		dot_product = np.dot(v1, v2)
		norm_v1 = np.linalg.norm(v1)
		norm_v2 = np.linalg.norm(v2)
		if norm_v1 == 0 or norm_v2 == 0:
			return 0
		return dot_product / (norm_v1 * norm_v2)

	# OpenAI 임베딩
	openai_client = OpenAI()
	response = openai_client.embeddings.create(
		input = "The king is the prince's father",
		model = "text-embedding-3-large"
	)
	king_vector = np.array(response.data[0].embedding)
	print(response.usage)
	print(king_vector.shape)

	# Upstage 임베딩 (OpenAI SDK 호환 : api_key와 base_url만 교체)
	upstage_client = OpenAI(
		api_key = upstage_key,
		base_url="https://api.upstage.ai/v1"
	)
	response = upstage_client.embeddings.create(
		input = "왕은 왕자의 아버지다",
		model="embedding-query"
	)
	up_kor_king_vector = np.array(response.data[0].embedding)

	print(cosine_similarity(king_vector, up_kor_king_vector))

4.2 tiktoken 직접 분할

- tiktoken은 OpenAI 공식 tokenizer 라이브러리
- 변환 흐름 : 문자 → 토큰 정수 리스트 → 문자 복원
- 글자 수와 토큰 수는 서로 다른 값
- 토큰 리스트를 chunk_size 간격으로 슬라이싱하여 분할

	ex)
	import tiktoken

	def split_text(full_text, chunk_size=1500):
		'full_text를 chunk_size로 분할하여 chunk_list로 반환'
		encoder = tiktoken.encoding_for_model('gpt-4o-mini')
		total_encoding = encoder.encode(full_text)
		total_token_count = len(total_encoding)

		chunk_list = []
		for i in range(0, total_token_count, chunk_size):
			chunk_encoding = total_encoding[i : i+chunk_size]
			chunk_decoded = encoder.decode(chunk_encoding)
			chunk_list.append(chunk_decoded)
		return chunk_list

4.3 TokenTextSplitter

- token 단위로 chunk_overlap만큼 겹쳐서 분할
- overlap : 인접 chunk 간 문맥 단절 방지 목적

- encoding_name 종류
	- o200k_base : gpt-4o, gpt-4o-mini 등 최신 세대 모델용
	- cl100k_base : gpt-4, gpt-3.5-turbo, text-embedding-3 등에서 쓰이는 표준 인코딩
	- p50k_base : text-davinci-003, Codex 등 구버전 모델용
	- r50k_base (또는 gpt2) : GPT-2, 구버전 GPT-3 호환용 레거시 인코딩

	ex)
	from langchain_text_splitters import TokenTextSplitter
	text_splitter = TokenTextSplitter(
		encoding_name="cl100k_base",
		chunk_size=1500,
		chunk_overlap=200
	)
	documents = loader.load_and_split(text_splitter=text_splitter)


4.4 RecursiveCharacterTextSplitter

- 글자 수 기준 분할
- separators 리스트 순서대로 분할 기준 우선순위 적용
	- 큰 구분자부터 시도하여 문단 단위 의미 유지
- load_and_split 또는 load 후 split_documents로 사용

	ex)
	from langchain_text_splitters import RecursiveCharacterTextSplitter
	text_splitter = RecursiveCharacterTextSplitter(
		chunk_size=1500,
		chunk_overlap=200,
		separators=["\n\n\n\n", "\n\n", "\n", " "] # 분할 기준 우선순위
	)
	documents = loader.load_and_split(text_splitter=text_splitter)

	# 각 chunk의 글자 수 확인
	print(np.array([len(d.page_content) for d in documents]).mean())
	print(min([len(d.page_content) for d in documents]))
	print(max([len(d.page_content) for d in documents]))

5.3 Pinecone (cloud)

- index_name 단위로 관리

- 인덱스 생성 조건 : name, dimension, metric, spec(ServerlessSpec의 cloud, region)
	- dimension은 임베딩 벡터 길이와 일치 필요
	- 임베딩 모델별로 인덱스 분리 관리

- 기존 인덱스를 확인하여 없을 경우에만 생성하고 ready 상태가 될 때까지 대기

- 첫 저장은 from_documents, 이후에는 생성자로 로드
	- 첫 저장 코드는 재실행 시 중복 저장되므로 저장 후 주석 처리

- 인덱스 데이터 전체 삭제는 delete(delete_all=True), 인덱스 삭제는 delete_index
	- 비어 있는 인덱스에서 삭제 시 에러가 발생할 수 있어 chunk 하나를 먼저 저장

	ex)
	import time
	from pinecone import Pinecone, ServerlessSpec
	from langchain_pinecone import PineconeVectorStore

	pc = Pinecone()
	index_name = 'tax-index'
	dimension = len(embedding.embed_query("차원 확인용"))

	if not pc.has_index(index_name):
		pc.create_index(
			name=index_name,
			dimension=dimension,
			metric="cosine",
			spec=ServerlessSpec(cloud='aws', region='us-east-1')
		)
		while not pc.describe_index(index_name).status['ready']:
			time.sleep(1)

	# 데이터 첫 저장 시
	database = PineconeVectorStore.from_documents(
		documents=documents,
		embedding=embedding,
		index_name=index_name
	)

	# vectorDB 로드 시
	database = PineconeVectorStore(
		embedding=embedding,
		index_name=index_name
	)

	# 인덱스 정보 확인
	index = pc.Index(index_name)
	print(index.describe_index_stats())

7. RAG chain 구성 (LCEL)

- ChatPromptTemplate : 템플릿 변수 query, context에 값을 동적으로 주입
	- f-string 내에서 템플릿 변수는 이중 중괄호로 이스케이프 처리

- StrOutputParser : AI 응답 객체를 문자열로 변환
- format_documents : 검색된 Document 리스트를 하나의 문자열로 변환

- 체인 구성
	- 딕셔너리로 context와 query를 병렬 전달
	- RunnablePassthrough는 입력 질문을 그대로 전달
	- prompt, llm, StrOutputParser를 파이프 연산자로 순차 연결

	ex)
	from langchain_core.prompts import ChatPromptTemplate
	from langchain_core.output_parsers import StrOutputParser
	from langchain_core.runnables import RunnablePassthrough

	template = f'''당신은 최고의 한국 소득세법 전문가입니다. 다음 문맥을 참고하여 질문에 최대 5문장으로 답하세요. 답을 모르면 모른다고 답하세요.
	질문 : {{query}}
	문맥 : {{context}}
	답변 : '''
	prompt = ChatPromptTemplate.from_template(template)

	def format_documents(retrieved_docs):
		return "\n--\n".join([doc.page_content.replace('\n\n', ' ') for doc in retrieved_docs])

	rag_chain = (
		{
			"context":retriever | format_documents,
			"query":RunnablePassthrough() # 질문만 그대로 전달
		}
		| prompt
		| llm
		| StrOutputParser()
	)

	rag_chain.invoke('연봉 5천만원인 직장인의 소득세는 얼마인가요?')

9. 키워드 사전을 이용한 질문 표준화

- 일반 사용자 표현과 법률 용어 사이의 임베딩 유사도가 낮으면 검색 정확도 저하
	- 직장인과 거주자, 연봉과 종합소득, 5천과 5,000 등

- 사전 형식 : 일반사용자 단어 -> 소득세법 용어
- LLM이 사전을 참고하여 질문을 법률 용어로 변환, 변환이 불필요하면 원문 유지

- keyword_chain을 rag_chain 앞에 연결하여 하나의 파이프라인 구성
	- 입력 질문 → 질문 수정 → 개선된 질문 → retriever → format_documents → prompt와 llm → 문자열 출력

	ex)
	keyword_dict  = [
		"사람을 나타내는 표현 -> 거주자",
		"직장인 -> 근로소득이 있는 거주자",
		"월급쟁이 -> 근로소득이 있는 거주자",
		"회사원 -> 근로소득이 있는 거주자",
		"연봉 -> 종합소득",
		"월급 -> 근로소득",

		"""
		content의 카테고리를 점수순으로 list 반환 (top_k만큼, None이면 전체)
		"""
		category_keywords = get_category()
		category_scores = {}
		for category, weighted_keywords in category_keywords.items():
			score = 0
			for keyword, weight in weighted_keywords.items():
				count = content.count(keyword) # content에 keyword가 나오는 횟수
				score += count * weight
			if score>0:
				category_scores[category] = score
		sorted_categories = sorted(category_scores.items(), key=lambda item:item[1], reverse=True)
		all_categories = [category[0] for category in sorted_categories]
		if not all_categories:
			all_categories = ["기타"]
		if top_k is not None:
			return all_categories[:top_k]
		return all_categories

	def get_article(content):

		article_match = re.findall(r"제(\d{1,3}조)", content)

		return ""

13. rerank (재정렬)
- 벡터 유사도 검색으로 후보를 넉넉히 확보(k=10)한 뒤 질문과의 관련도 기준으로 다시 정렬하여 상위 top_k개만 사용
- 재정렬 대상 텍스트는 title과 page_content

13.1 cohere rerank API

- rerank-multilingual-v3.0 모델 사용, .env에 COHERE_API_KEY 필요
- 결과의 index 값으로 원본 Document 객체 복원
- top_n 인자로 반환 문서 개수 지정
- 의미 기반 재정렬이 가능하나 API 호출 비용과 지연 시간 발생

	ex)
	import cohere

	def rerank_by_title(query:str, documents:list, top_k:int=3) -> list:
		'''
		cohere의 rerank API를 사용한 documents 재정렬
		'''
		docs_text = [doc.metadata.get('title')+' '+doc.page_content for doc in documents]
		co = cohere.Client()

			model = 'rerank-multilingual-v3.0',

			top_n=top_k
		)
		return [documents[r.index] for r in results.results]


13.2 TfidfVectorizer 방식

- 외부 API 없이 scikit-learn으로 로컬 계산
- analyzer='char' : 한국어는 띄어쓰기 단위 분리가 부정확하므로 글자 단위 분석
- ngram_range=(2, 3) : 2~3글자 조합 사용

- 처리 흐름
	- query와 title을 하나의 리스트로 결합하여 fit_transform
	- 0번째 행은 query 벡터, 나머지 행은 title 벡터로 분리
	- 코사인 유사도 계산 후 내림차순 정렬하여 top_k개 반환

- 비용과 지연 시간이 없으나 글자 중복 기반이라 의미 파악 능력은 cohere보다 제한적

	ex)
	from sklearn.feature_extraction.text import TfidfVectorizer
	from sklearn.metrics.pairwise import cosine_similarity

	def rerank_by_title(query:str, documents:list, top_k:int=3) -> list:
		'''
		sklearn의 TfidfVectorizer를 사용한 documents 재정렬
		'''
		titles = [doc.metadata.get('title')+' ' for doc in documents]

		vectorizer = TfidfVectorizer(
			analyzer='char',
			ngram_range=(2, 3)
		)

		all_texts = [query] + titles
		tfidf_matrix = vectorizer.fit_transform(all_texts)
		query_vector = tfidf_matrix[0:1]
		title_vector = tfidf_matrix[1:]
		similarities = cosine_similarity(query_vector, title_vector)[0]

		score_docs = list(zip(similarities, documents))
		score_docs.sort(key=lambda x : x[0], reverse=True)
		rerank_docs = [score_doc[1] for score_doc in score_docs]
		if top_k:
			return rerank_docs[:top_k]
		return rerank_docs
