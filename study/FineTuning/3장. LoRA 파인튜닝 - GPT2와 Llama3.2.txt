3장. LoRA 파인튜닝 - GPT-2 와 Llama-3.2


0. 모델 정보 비교

- distilbert-base-uncased (BERT 계열) 대비 gpt2 특성
	- 모델 타입 : Decoder (GPT 계열), 사전학습 목적 : 오토리그레시브 언어 생성 (Next token)
	- 파라미터 약 124M, 레이어 12개, 히든 크기 768, 어텐션 헤드 12개
	- 최대 시퀀스 길이 1024 tokens, 토크나이저 BPE
	- 생성 능력 있음 (텍스트 생성, 요약, 질문응답 등)
	- 연산 효율성 : 텍스트 생성의 연속 수행 필요로 상대적으로 느림

- gpt2 대비 Llama-3.2-Korean-GGACHI-1B-Instruct-v1 특성
	- 모델 타입 : Decoder (Llama 계열)
	- 사전학습 목적 : 오토리그레시브 언어 생성 + 한국어 데이터 지시 튜닝 (GGACHI)
	- 파라미터 약 1.2B (GPT-2의 약 10배), 레이어 16개, 히든 크기 2,048
	- 어텐션 헤드 32개 (KV 헤드 8개, GQA 구조)
	- 최대 시퀀스 길이 수만 토큰 이상 (이 노트북은 64 tokens만 사용)
	- 토크나이저 : BPE (어휘 약 12.8만 개, GPT-2는 약 5만 개)
	- 한국어 : GPT-2는 거의 불가, Llama GGACHI는 한국어 데이터로 추가 튜닝
	- 학습 방식 : fp16 혼합 정밀도 + LoRA (양자화 없음)
	- GGACHI는 Llama-3.2-1B-Instruct를 한국어 데이터로 추가 파인튜닝한 모델

3. 모델 및 토크나이저 로드

3.1 공통 개념

- 토크나이저 : 텍스트를 숫자 시퀀스로 바꿔주는 도구

- pad_token 처리
	* GPT-2는 pad_token이 기본 제공되지 않아 eos_token을 pad_token으로 설정
	* Llama 계열도 pad_token이 기본 제공되지 않는 경우가 많아 없을 때만 eos_token으로 대체
	* eos_token : 문장의 끝을 모델에게 알려주어 텍스트 생성 중지

3.2 GPT-2 로드

	ex)
	model_id = "gpt2"  # 사용할 모델 지정 (GPT-2)
	tokenizer = AutoTokenizer.from_pretrained(model_id)
	tokenizer.pad_token = tokenizer.eos_token
	model = AutoModelForCausalLM.from_pretrained(model_id)

3.3 Llama 3.2 1B 로드

- 1B 모델은 양자화 없이 fp32로 올려도 가중치가 약 5GB라서 T4(16GB)에 충분히 적재
	* 최신 transformers는 dtype 미지정 시 bf16으로 로드하나 T4는 bf16을 제대로 지원하지 않음
	* float() 호출로 fp32 변환 후 to("cuda")로 GPU 이동 (학습 때는 fp16=True 혼합 정밀도 사용)
	* float()는 transformers 버전에 상관없이 동작하므로 dtype, torch_dtype 인자 이름 고려 불필요

	ex)
	# 모델 다운로드에서 401/403 오류가 나면 아래 주석을 풀고 실행 (Hugging Face 토큰 필요)
	# 모델 페이지에서 라이선스 동의가 필요할 수도 있음

	# 다른 후보: "vitus9988/Llama-3.2-1B-Instruct-Ko-SFT"

	set_seed(42)

4. LoRA 설정

4.1 LoRA 개념

- LoRA(Low-Rank Adaptation) : 대규모 모델을 가볍게 미세조정할 수 있게 해주는 기술
	* 전체 모델을 학습시키지 않고, 일부 작은 파라미터만 추가로 학습

- LoraConfig 주요 파라미터
	* r : 랭크, LoRA 내부 차원 (작을수록 가볍고 빠름)
	* lora_alpha : 학습 안정성을 위한 스케일링 계수
	* target_modules : LoRA를 적용할 레이어
	* lora_dropout : 드롭아웃 적용 (과적합 방지)
	* bias="none" : bias 파라미터 학습 제외
	* task_type : 작업 유형 (CAUSAL_LM, 언어 생성)

4.2 모델별 대상 레이어 비교

- GPT-2의 레이어
	* c_attn : 쿼리, 키, 밸류를 생성하는 핵심 어텐션 입력 레이어
	* c_proj : 어텐션 출력 벡터를 변환하는 투영 레이어
	* q_attn : self-attention 중 쿼리 연산에 관여하는 부분 (GPT-J 등 일부 구조에 존재)
	* mlp.c_fc : 피드포워드 네트워크의 첫 번째 선형 계층 (MLP의 입력 부분)
	* mlp.c_proj : MLP의 출력 부분

- Llama의 레이어 (GPT-2와 이름이 다름)
	* q_proj, k_proj, v_proj : 어텐션의 쿼리, 키, 밸류를 각각 만드는 선형 레이어 (GPT-2에서는 c_attn 하나가 담당)
	* o_proj : 어텐션 출력 벡터를 변환하는 투영 레이어 (GPT-2의 c_proj에 해당)
	* gate_proj, up_proj : MLP의 입력 부분 (GPT-2의 mlp.c_fc에 해당)
	* down_proj : MLP의 출력 부분 (GPT-2의 mlp.c_proj에 해당)

- GPT-2는 Conv1D 레이어라서 fan_in_fan_out 경고 발생 (자동으로 True로 설정), Llama는 일반 Linear 레이어라서 경고 없음

4.3 GPT-2 LoRA 적용

- get_peft_model 적용과 동시에 to("cuda")로 GPU 이동

	ex)
	lora_config = LoraConfig(
		r=8,  # 랭크: LoRA 내부 차원. 작을수록 가볍고 빠름
		lora_alpha=16,  # 학습 안정성을 위한 스케일링 계수
		target_modules=["c_attn","c_proj","q_attn"],  # GPT-2에서 LoRA를 적용할 레이어
		lora_dropout=0.05,  # 드롭아웃 적용 (과적합 방지)
		bias="none",  # bias 파라미터는 학습하지 않음
		task_type=TaskType.CAUSAL_LM,  # 작업 유형: 언어 생성 (Causal Language Modeling)
	)

	# 모델에 LoRA 설정을 적용
	model = get_peft_model(model, lora_config).to("cuda")

	# 실제로 학습 가능한 파라미터 수 출력
	model.print_trainable_parameters()

	# 모델이 GPU에 있는지 확인
	print("모델 위치:", model.device)


4.4 Llama LoRA 적용

- 모델이 이미 GPU에 올라가 있으므로 LoRA 적용 후 to("cuda") 재호출 불필요
- 학습 시 use_cache=False 설정 (캐시 비활성화)
- r=16, lora_alpha=32로 GPT-2 대비 상향, 어텐션과 MLP 7개 레이어 모두 적용
- 학습 가능 파라미터 11,272,192개 (전체 1,247,086,592개 중 0.9039%)
- GPU 메모리 사용량 약 4.6GB 확인

	ex)
	model.config.use_cache = False  # 학습 시에는 캐시 비활성화

	lora_config = LoraConfig(
		r=16,  # 랭크: LoRA 내부 차원. 작을수록 가볍고 빠름
		lora_alpha=32,  # 학습 안정성을 위한 스케일링 계수
		target_modules=["q_proj", "k_proj", "v_proj", "o_proj",
						"gate_proj", "up_proj", "down_proj"],  # Llama에서 LoRA를 적용할 레이어
		lora_dropout=0.05,  # 드롭아웃 적용 (과적합 방지)
		bias="none",  # bias 파라미터는 학습하지 않음
		task_type=TaskType.CAUSAL_LM,  # 작업 유형: 언어 생성 (Causal Language Modeling)
	)

	# 모델에 LoRA 설정을 적용 (모델은 이미 GPU에 있음)
	model = get_peft_model(model, lora_config)

	# 실제로 학습 가능한 파라미터 수 출력
	model.print_trainable_parameters()

	# 모델이 GPU에 있는지 확인
	print("모델 위치:", model.device)
	print(f"GPU 메모리 사용: {torch.cuda.memory_allocated() / 1024**3:.1f} GB")

6. 토크나이즈 함수

6.1 GPT-2 방식

- 텍스트 데이터를 모델 입력용 숫자 형태(토큰 ID)로 변환
- padding과 truncation 설정을 통한 입력 길이 일정화 (max_length=64)

	ex)
	def tokenize_function(example):
		return tokenizer(example["text"], padding="max_length",
						truncation=True,
						max_length=64)

	# 데이터셋에 토크나이즈 함수를 적용하여 숫자형 시퀀스로 변환
	tokenized_dataset = dataset.map(tokenize_function)

6.2 Llama 방식

- 문장 끝에 EOS 토큰 직접 추가
	* Llama 토크나이저는 문장 앞에 BOS는 붙이지만 끝에 EOS는 붙이지 않음
	* EOS를 학습하지 않으면 답변이 끝나도 모델이 멈추지 않고 계속 생성

- labels 직접 생성 : 패딩 위치만 -100으로 설정하여 손실 계산에서 제외
	* pad_token이 eos_token과 같을 때 DataCollatorForLanguageModeling을 쓰면 진짜 EOS까지 같이 가려짐
	* 따라서 attention_mask를 기준으로 패딩만 마스킹

- 길이 점검 : 최대 토큰 길이 35 / 64 확인 (MAX_LENGTH에 닿으면 문장 끝 EOS가 잘렸을 가능성)
- batched=True 및 remove_columns로 원본 text 컬럼 제거

	ex)
	MAX_LENGTH = 64

	def tokenize_function(examples):
		# 문장 끝에 EOS를 붙여서 "여기서 답변을 끝내라"를 학습시킴
		texts = [t + tokenizer.eos_token for t in examples["text"]]
		out = tokenizer(texts, padding="max_length",
						truncation=True,
						max_length=MAX_LENGTH)
		# 패딩(attention_mask=0) 위치만 -100 → 손실 계산에서 제외 (진짜 EOS는 학습 대상으로 유지)
		out["labels"] = [
			[tok if m == 1 else -100 for tok, m in zip(ids, mask)]
			for ids, mask in zip(out["input_ids"], out["attention_mask"])
		]
		return out

	# 데이터셋에 토크나이즈 함수를 적용하여 숫자형 시퀀스로 변환
	tokenized_dataset = dataset.map(tokenize_function, batched=True, remove_columns=["text"])

	# 길이 점검: MAX_LENGTH에 닿으면 문장 끝(EOS)이 잘렸을 수 있음
	lengths = [sum(x["attention_mask"]) for x in tokenized_dataset]
	print("최대 토큰 길이:", max(lengths), "/", MAX_LENGTH)
	if max(lengths) >= MAX_LENGTH:
		print("일부 샘플이 잘렸을 수 있어요. MAX_LENGTH를 늘려 주세요.")

	* mlm=True는 BERT처럼 Masked Language Modeling 모델에서 사용

7.2 Llama 방식

- 앞 단계에서 모든 샘플을 같은 길이(64)로 맞추고 labels까지 생성했으므로 default_data_collator로 충분
- DataCollatorForLanguageModeling은 패딩과 EOS가 같은 토큰일 때 EOS가 가려지는 문제로 미사용
- 첫 샘플의 labels 디코딩 결과 확인 : 문장 맨 앞 BOS, 맨 끝 EOS가 보이면 정상

	# 첫 번째 샘플에서 학습 대상(labels) 부분만 디코딩해서 확인
	# 문장 맨 앞에 BOS, 맨 끝에 EOS가 보이면 정상

8. 트레이닝 설정

8.1 step 과 epoch 의 차이

- step : iteration과 동일한 의미로, 한 번의 파라미터 업데이트
- 모델이 한 배치(batch)를 보고 학습하는 것이 1 step (1 iteration)
- epoch : 전체 데이터를 한 바퀴 학습한 것
- 여러 step이 모여 하나의 epoch 구성

8.2 GPT-2 설정

- 데이터 30개, 배치 10개이므로 1 epoch = 3 step
- num_train_epochs=500으로 총 1500 step 학습
- fp16=True : GPU 없이 CPU로 학습 시 False 설정

	ex)
	training_args = TrainingArguments(
		output_dir="./results",  # 결과 디렉토리
		per_device_train_batch_size=10,  # GPU나 CPU 1개당 배치 사이즈
		num_train_epochs=500,  # 데이터 전체를 몇 번 반복해서 학습할지
		logging_steps=50,  # 50스텝마다 로그 출력 (학습 진행 상황 확인)
		save_strategy="no",  # 중간 저장 생략 (데모 목적이므로)
		fp16=True,  # GPU 없이 CPU로 학습 시 False 설정,
		report_to = "none",  # wandb, tensorboard 등 외부 로깅 툴 비활성화
	)


8.3 Llama 설정

- GPT-2(500 epoch)보다 큰 모델이므로 학습률을 높이고(2e-4) 반복 횟수는 축소 (30 epoch = 90 step)
- 답변이 덜 외워졌으면 num_train_epochs 증가 필요
- learning_rate=2e-4 : LoRA 학습에 흔히 쓰는 학습률
- warmup_steps=5 : 처음 5스텝 동안 학습률을 서서히 증가

	ex)
	training_args = TrainingArguments(
		output_dir="./results",  # 결과 디렉토리

		num_train_epochs=30,  # 데이터 전체를 몇 번 반복해서 학습할지
		learning_rate=2e-4,  # LoRA 학습에 흔히 쓰는 학습률

9. 트레이너 설정 및 학습 시작

9.1 GPT-2

- Hugging Face Trainer 클래스를 활용한 학습 진행
- compute_metrics : 정답 토큰 예측 정확도 계산 (labels가 -100인 패딩 위치는 무시)
- processing_class : 최신 버전(4.46 이상)의 토크나이저 전달 인자 (구버전 4.45 이하는 tokenizer)
- 학습 결과 : 1500 step, training_loss 약 0.394, 소요 시간 약 146초

	ex)
	import numpy as np
	# 정확도를 계산하는 함수 정의
	def compute_metrics(eval_pred):
		logits, labels = eval_pred
		predictions = np.argmax(logits, axis=-1)

		# padding 부분은 무시
		mask = labels != -100
		correct = (predictions == labels) & mask
		accuracy = correct.sum() / mask.sum()

		return {"accuracy": accuracy}

	trainer = Trainer(
		model=model,  # 학습할 모델
		args=training_args,  # 학습 설정
		train_dataset=tokenized_dataset,  # 학습 데이터
		# tokenizer=tokenizer,  # 텍스트 디코딩용(구버전 (4.45 이하))
		processing_class=tokenizer, # 최신 버전 (4.46 이상)
		data_collator=data_collator,  # 배치 구성 도우미
		compute_metrics=compute_metrics  # 정확도 계산 함수 추가
	)

	# 학습
	trainer.train()

10. 결과 확인

10.1 GPT-2

- 질문 프롬프트를 토크나이징 후 모델이 있는 디바이스로 입력 이동

- generate 주요 파라미터
	* max_new_tokens : 최대 50개의 새로운 토큰 생성
	* do_sample=True : 다양한 답변 생성
	* temperature=0.7 : 창의성 조절
	* repetition_penalty=1.2 : 같은 말 반복 방지

- skip_special_tokens=True : 시작/종료 같은 특수 기호 미출력

- 출력 결과 : 한글이 깨지고 영어 문장이 섞여 나오는 등 의도한 답변(순둥이) 미생성
	* 한국어 사전학습이 거의 없는 GPT-2의 한계

	ex)
	# "우리집 강아지 이름은?"이라는 질문에 답을 하도록 구성
	input_text = "### 질문:우리집 강아지 이름은?\n### 답변:"

	# 입력 문장을  PyTorch 텐서 형태로 반환
	inputs = tokenizer(input_text, return_tensors="pt")

	# 모델이 올라가 있는 디바이스(GPU 또는 CPU) 선택
	device = model.device

	# 모델이 있는 디바이스로 입력 데이터 이동
	inputs = {k: v.to(device) for k, v in inputs.items()}

	# 답변 생성
	outputs = model.generate(
		**inputs,
		max_new_tokens=50,       # 최대 50개의 새로운 단어(토큰) 생성
		do_sample=True,          # 다양한 답변 생성
		temperature=0.7,         # 창의성 조절
		repetition_penalty=1.2,  # 같은 말 반복 방지
	)

	# 생성된 답변을 사람이 읽을 수 있는 문자열로 바꿔 출력
	print(tokenizer.decode(
		outputs[0],
		skip_special_tokens=True # 시작/종료 같은 특수 기호 미출력
	))

10.2 Llama

- 학습한 질문, 표현만 바꾼 질문, 학습하지 않은 일반 질문을 함께 입력하여 확인
- 생성 시에는 use_cache=True 재활성화 (속도 향상) 및 model.eval() 전환

- do_sample=False : 학습 확인을 위해 매번 같은 답 생성 (다양한 답변은 do_sample=True, temperature=0.7)
- eos_token_id : 학습 때 붙인 EOS가 나오면 생성 중지

- 입력 프롬프트 부분은 잘라내고 새로 생성된 부분만 출력

- 출력 결과
	* 학습한 질문 및 표현을 바꾼 질문 : 순둥이 답변 정상 생성
	* 학습하지 않은 일반 질문(바다는 왜 파란가요?) : 기존 지식이 유지되어 일반 답변 생성

	ex)
	model.config.use_cache = True  # 생성 시에는 캐시 다시 켜기 (속도)
	model.eval()

	def ask(question, max_new_tokens=50):
		prompt = f"### 질문:{question}\n### 답변:"
		inputs = tokenizer(prompt, return_tensors="pt").to(model.device)  # 모델이 있는 디바이스로 이동
		with torch.no_grad():
			outputs = model.generate(
				**inputs,
				max_new_tokens=max_new_tokens,  # 최대 50개의 새로운 토큰 생성
				do_sample=False,
				eos_token_id=tokenizer.eos_token_id,
				pad_token_id=tokenizer.pad_token_id,
			)
		new_tokens = outputs[0][inputs["input_ids"].shape[1]:]  # 프롬프트 뒷부분만
		return tokenizer.decode(new_tokens, skip_special_tokens=True).strip()

	questions = [
		"우리집 강아지 이름은?",       # 학습한 질문
		"강아지 이름 좀 알려줄래?",     # 표현만 바꾼 질문
		"순둥이가 누구야?",            # 학습한 질문
		"바다는 왜 파란가요?",          # 학습하지 않은 일반 질문 (기존 지식이 유지되는지 확인)
	]
	for q in questions:
		print(f"Q: {q}")
		print(f"A: {ask(q)}\n")
